# 배포 호환성 안내 — 어디에 올려도 같은 앱이 돌게

작성 2026-10-08. 이 앱은 **Python 3.11 + Streamlit + SQLite 파일 하나**로 구성돼 있어 특정 클라우드에 묶이지 않는다. 현재는 개인 Google Cloud Run에 올려 쓰고 있지만, 회사 공용 서버(사내 리눅스/윈도우)나 다른 클라우드(AWS·Azure·네이버 클라우드)로 옮길 때 바꿀 것은 **환경변수와 기록 파일 위치**뿐이다.

## 1. 어디에 올릴 수 있나

| 환경 | 실행 방법 | 기록 DB 보존 | AI 호출 | 비고 |
|---|---|---|---|---|
| 담당자 PC(Windows) | `run.bat` | `storage/history.db` 파일 | 설정 화면에 본인 키 | 혼자 쓰기. 기본 |
| 사내 공용 서버 — Windows | `run_server.bat` | `storage/` 또는 `APP_STORAGE_DIR` | 서버 환경변수 공용 키 또는 각자 키 | 같은 망 안에서 여러 명. 앞에 IIS/nginx로 HTTPS 권장 |
| 사내 공용 서버 — Linux Docker | `docker compose up -d --build` | 볼륨 `/data` | 위와 같음 | `.env.example` → `.env`. 상태 확인 `/_stcore/health` |
| Google Cloud Run(현재) | `deploy_cloudrun.ps1`/`.sh` | Litestream → GCS 버킷 | 위와 같음 | `docs/배포_클라우드.md` |
| AWS App Runner / ECS Fargate | 같은 Dockerfile | Litestream → S3 (`s3://버킷/history`) | Anthropic 직접, 또는 **Claude Platform on AWS**(`aws`)·**Bedrock**(`bedrock`) 공급자 | 인스턴스 1개 고정 |
| Azure Container Apps | 같은 Dockerfile | Litestream → Blob (`abs://계정/컨테이너/history`) + `LITESTREAM_AZURE_ACCOUNT_KEY` | Anthropic 직접 | 복제본 1개 고정 |
| 네이버 클라우드(NCP) 컨테이너 | 같은 Dockerfile | Litestream → Object Storage(S3 호환): `s3://버킷/history` + `LITESTREAM_ENDPOINT=https://kr.object.ncloudstorage.com` | Anthropic 직접 | 공공기관 망 분리 요건이 있으면 이 쪽 |
| GCP Vertex AI로 모델만 바꾸기 | 어느 환경이든 | — | `vertex` 공급자(서비스 계정 인증, 키 불필요) | 모델 ID는 Model Garden 기준 [확인 필요] |

공통 제약: **인스턴스(복제본)는 1개**로 고정한다. SQLite 파일 하나를 여러 컨테이너가 동시에 쓰면 기록이 깨진다. 동시 접속자 40명 수준까지는 1개로 충분하다(현 설정 `--concurrency 40`).

## 2. 환경변수 한눈에

| 변수 | 뜻 | 기본 |
|---|---|---|
| `APP_PASSWORD` | 접속 비밀번호(10자 이상). 비우면 잠금 없음 | 없음 |
| `APP_ADMIN_PASSWORD` | 백업 내려받기·복원·전체 삭제용 관리자 비밀번호 | `APP_PASSWORD`와 같음 |
| `APP_STORAGE_DIR` | 기록 DB·회신 파일·백업 폴더 | `app/storage` (컨테이너 `/data`) |
| `HISTORY_DB` | 기록 DB 파일 경로(폴더만 바꾸면 위 변수로 충분) | `<APP_STORAGE_DIR>/history.db` |
| `APP_BACKUP_KEEP` | 서버 안 자동 사본 보존 개수 | 10 |
| `LLM_PROVIDER` | 기본 AI 공급자: `anthropic`·`aws`·`bedrock`·`vertex`·`openai`·`gemini`·`none` | anthropic |
| `ANTHROPIC_API_KEY` 등 | 서버 공용 키(두면 접속자 전원이 이 키로 호출) | 없음 → 각자 설정 화면에 입력 |
| `ANTHROPIC_BASE_URL` / `OPENAI_BASE_URL` / `GEMINI_BASE_URL` | 사내 API 게이트웨이·프록시 주소 | 공식 주소 |
| `LLM_MODEL`, `LLM_EFFORT` | 기본 모델·추론 강도 | 공급자 기본 |
| `LLM_DAILY_BUDGET_USD` | 하루 AI 사용 상한(추정 달러, 서버 전체). 넘으면 그날은 규칙 기반만 | 없음 |
| `HTTPS_PROXY` | 바깥으로 나가는 프록시 | 없음 |
| `LITESTREAM_REPLICA_URL` | 기록 DB 복제 대상(`gcs://`·`s3://`·`abs://`·`file://`) | 없음(볼륨만) |
| `LITESTREAM_ENDPOINT`, `LITESTREAM_PATH_STYLE`, `LITESTREAM_ACCESS_KEY_ID`, `LITESTREAM_SECRET_ACCESS_KEY`, `LITESTREAM_AZURE_ACCOUNT_KEY` | S3 호환·Azure 복제 설정 | 없음 |
| `APP_NO_CDN` | 1이면 외부 폰트 불러오기 끔(인터넷 차단 망) | 없음 |
| `APP_DB_ON_CORRUPT` | `stop`이면 DB 손상 시 멈춤(복제 켜진 서버는 자동) | 로컬은 비켜 두고 새로 만듦 |
| `STREAMLIT_ERROR_DETAILS` | 화면 오류 상세 수준(`type`/`full`) | 컨테이너 `type` |
| `STREAMLIT_SERVER_BASE_URL_PATH` | 리버스 프록시 경로 접두(`ebs` → `/ebs/`) | 없음 |
| `TZ` | 시간대(기한 계산·기록 시각) | `Asia/Seoul` |
| `DEPT_HEAD`, `DEPT_PHONE` | 【확인】 줄 기본값(설정 화면 저장값이 우선) | 없음 |
| `AWS_REGION`, `ANTHROPIC_AWS_WORKSPACE_ID`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` | `aws`·`bedrock` 공급자 | 없음 |
| `ANTHROPIC_VERTEX_PROJECT_ID`, `CLOUD_ML_REGION` | `vertex` 공급자 | 없음 |

## 3. 사내 공용 서버(Linux Docker) 설치 순서

```
git clone <저장소> && cd ebsjajucenter/app
cp .env.example .env            # APP_PASSWORD(10자 이상)·공용 키·하루 상한을 채운다. .env는 저장소에 넣지 않는다
docker compose up -d --build
curl -s http://localhost:8080/_stcore/health     # ok 가 나오면 정상
```
- 기록은 Docker 볼륨 `app-data`(`/data`)에 남는다. 서버 백업 정책에 이 볼륨을 포함시킨다(`docker run --rm -v app-data:/data -v $PWD:/b alpine tar czf /b/app-data.tgz /data`).
- 사내망 밖에서도 접속하게 하려면 앞에 nginx 등 **TLS 리버스 프록시**를 둔다(아래). 평문 HTTP로는 비밀번호·자료가 그대로 지나간다.
- Windows 서버는 Docker 없이 `run_server.bat`(0.0.0.0:8501)로도 되며, 이때 `APP_STORAGE_DIR`을 서버 백업 대상 폴더로 잡는다.

nginx 예시(웹소켓 필수):
```
server {
  listen 443 ssl;  server_name ebs.intranet.example;
  ssl_certificate /etc/ssl/ebs.crt;  ssl_certificate_key /etc/ssl/ebs.key;
  client_max_body_size 60m;
  location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_http_version 1.1;  proxy_set_header Upgrade $http_upgrade;  proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;  proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;  proxy_set_header X-Forwarded-Proto https;
    proxy_read_timeout 3600;
  }
}
```
경로 접두(`https://intranet/ebs/`)로 붙일 때는 `location /ebs/ { proxy_pass http://127.0.0.1:8080/ebs/; … }`와 환경변수 `STREAMLIT_SERVER_BASE_URL_PATH=ebs`를 함께 준다.

## 4. 다른 클라우드로 옮길 때

1. 같은 `Dockerfile`로 이미지를 만든다(루트가 아닌 계정으로 실행, 포트 `PORT`, 상태 확인 `GET /_stcore/health`).
2. 기록 보존은 둘 중 하나: **영구 볼륨**을 `/data`에 붙이거나, **객체 저장소 복제**(`LITESTREAM_REPLICA_URL`)를 켠다. 복제를 켜면 컨테이너가 사라져도 다음 시작 때 자동 복원된다. 복제 저장소에 접근하지 못하면 앱은 일부러 뜨지 않는다(빈 기록으로 덮어쓰는 사고 방지).
3. 비밀값(`APP_PASSWORD`, API 키, 복제 자격증명)은 그 플랫폼의 비밀 저장소로 넣는다: GCP Secret Manager(`--set-secrets`), AWS Secrets Manager/SSM, Azure Key Vault. 환경변수 평문은 콘솔·배포 이력에 남는다.
4. 바깥으로 나가는 통신 허용 목록(방화벽·프록시):
   - `api.anthropic.com`(Anthropic) · `api.openai.com`(OpenAI) · `generativelanguage.googleapis.com`(Gemini) — 쓰는 공급자만
   - 복제 저장소 엔드포인트(GCS·S3·Blob)
   - 빌드 때만: `pypi.org`·`files.pythonhosted.org`(pip), `github.com`·`objects.githubusercontent.com`(Litestream 내려받기)
   - 선택: `cdn.jsdelivr.net`(화면 글꼴. `APP_NO_CDN=1`이면 불필요)
5. 시간대 `TZ=Asia/Seoul`을 준다(기한 계산·기록 시각).
6. 옮긴 뒤 설정 → 백업·초기화에서 **백업 파일을 내려받아** 새 서버에 **복원**하면 기록이 그대로 이어진다(복원은 integrity 검사·표 구조 검사를 거친다).

## 5. AI 공급자 바꾸기

- 회사가 **AWS 계약**으로 Claude를 쓰기로 하면: `LLM_PROVIDER=aws`(Claude Platform on AWS — 기능·모델 ID가 공식 API와 같음, IAM 인증) 또는 `LLM_PROVIDER=bedrock`(Amazon Bedrock — 모델 ID는 Bedrock 콘솔 값, 서버 측 거절 대체 기능 없음). 둘 다 `pip install "anthropic[aws]"` / `"anthropic[bedrock]"`가 필요하며 `requirements.txt`에는 넣지 않았다(기본 설치를 가볍게). Dockerfile에 한 줄 추가하면 된다.
- **GCP 안에서 키 없이** 쓰려면 `LLM_PROVIDER=vertex` + Cloud Run 실행 서비스 계정에 Vertex AI 권한(`pip install "anthropic[vertex]"`).
- **사내 API 게이트웨이**가 있으면 `ANTHROPIC_BASE_URL`(서버 환경변수)로 준다. 접속자가 설정 화면에서 넣는 주소는 https·공인 호스트만 허용된다(서버를 거쳐 내부망을 읽는 경로 차단).
- 모델 ID·요금은 공급자마다 달라 Bedrock·Vertex 플러그인에는 기본 모델·단가를 비워 두었다 [확인 필요: 계약 시점의 콘솔 값].

## 6. 알려진 한계

- **인스턴스 1개**: 수백 명 동시 사용이나 무중단 이중화가 필요하면 SQLite 대신 PostgreSQL로 바꿔야 한다(`db.py` 한 곳에 모여 있어 가능하나 이번 범위 밖).
- **배포 중 겹침**: Cloud Run 리비전 교체 때 구·신 인스턴스가 잠시 같이 떠 둘 다 같은 복제본에 쓰려 할 수 있다. 사용자가 없는 시간에 배포하고, 배포 직후 설정 화면의 기록 건수를 확인한다. 더 엄격히 하려면 `--no-traffic`으로 올린 뒤 트래픽을 넘긴다.
- **회신 파일**: 승인·검토 요청 때 HWPX 본문을 기록 DB에도 넣으므로(2026-10-08부터) 컨테이너가 바뀌어도 내려받을 수 있다. 그 전 기록의 파일은 `out/` 폴더(볼륨)에만 있다.
