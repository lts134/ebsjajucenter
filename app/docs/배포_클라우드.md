# 서버에 올려서 쓰기 — 가능한 방법과 한계

## 결론부터
- **Firebase Hosting에는 올릴 수 없다.** Firebase Hosting은 정적 파일(HTML·JS)만 서비스하고, 이 앱은 파이썬 서버(Streamlit)가 돌아야 한다.
- 올릴 수 있는 곳: **Google Cloud Run**(Firebase와 같은 Google Cloud 안, 컨테이너 실행), Streamlit Community Cloud, Render·Railway·Fly.io 같은 컨테이너 호스팅, 또는 **사내 서버·공용 PC**(`run_server.bat`).
- 지금 코드는 이력을 **SQLite 파일**에 쓴다. 클라우드 컨테이너는 재시작·재배포 때 파일이 사라지므로, 클라우드에서는 **시연·심사용**으로만 맞다. 실사용(이력이 쌓여야 함)은 사내 서버에 두거나, DB를 Cloud SQL(PostgreSQL) 같은 외부 DB로 바꾸는 작업이 필요하다 [확인 필요: 사내 보안 규정상 국감 요구자료·내부 수치를 외부 클라우드에 둘 수 있는지].

## 방법 비교
| 방법 | 준비 | 비용(대략) | 이력 보존 | 적합 |
|---|---|---|---|---|
| 사내 공용 PC `run_server.bat` | 없음(지금 가능) | 0 | 유지 | 실사용 |
| Google Cloud Run (`deploy_cloudrun.sh`) | gcloud, 결제 프로젝트 | 상시 1인스턴스 기준 월 수천~수만 원대 [확인 필요] | 재배포·재시작 시 소실 | 시연·심사 |
| Streamlit Community Cloud | GitHub 연결, 무료 | 0 | 재시작 시 소실, 코드가 공개 저장소면 누구나 봄 | 시연(비공개 저장소 권장) |
| Render / Railway / Fly.io | 계정, Dockerfile(있음) | 무료~월 1만 원대 | 디스크 추가 시 유지 가능 | 시연·소규모 |

## Cloud Run으로 올리기(시연용)
1. Google Cloud 프로젝트 생성, 결제 연결, Cloud Run·Cloud Build API 사용 설정. PC에 gcloud CLI 설치 후 `gcloud auth login`.
2. 앱 폴더에서:
   ```
   PROJECT=내-프로젝트-id REGION=asia-northeast3 APP_PASSWORD=접속암호 ./deploy_cloudrun.sh
   ```
   (Windows는 Git Bash 또는 WSL에서 실행. 또는 명령을 그대로 PowerShell에 옮겨 적는다.)
3. 출력된 Service URL로 접속 → 접속 비밀번호 입력 → 설정 → AI 연결에 각자 키 입력.
4. 끝나면 `gcloud run services delete ebs-request-agent --region asia-northeast3`로 내린다(비용 중단).

## 보안 — 외부에 올릴 때 반드시
- `APP_PASSWORD`를 둔다(없으면 URL만 알면 누구나 들어옴). 비밀번호 하나로 모두가 들어오므로 실사용 인증은 아니다. 실사용이면 Cloud Run의 IAP(Identity-Aware Proxy)나 사내 SSO 앞단이 필요하다.
- API 키는 접속자 세션에만 보관되는 구조 그대로. 서버 환경변수에 공통 키를 두면 접속자 전원이 그 키로 호출해 비용이 한곳에 모인다.
- 올라가는 데이터: 업로드한 요구서·수치는 서버 메모리와 SQLite(/data)에 들어간다. 외부 클라우드에 내부 수치를 두는 것이 허용되는지 먼저 확인.

## 이력을 클라우드에서도 보존하려면(추후 작업)
- `db.py`가 sqlite3 직접 호출이므로 PostgreSQL로 바꾸려면 접속 계층 교체와 SQL 일부 수정(자동 증가 키·날짜 함수)이 필요하다. 하루 안팎 작업 [확인 필요].
- 간단한 대안: Cloud Run에 Cloud Storage 볼륨을 `/data`로 마운트. 단 SQLite가 네트워크 파일시스템 위에서 잠금 문제를 일으킬 수 있어 접속자 1~2명 시연에만 쓸 것.
