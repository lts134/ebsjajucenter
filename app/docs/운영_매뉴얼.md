# 운영 매뉴얼 — EBS 대외 요구자료 대응 에이전트

## 1. 설치·실행 (Windows PC)
1. Python 3.11 이상 설치(설치 시 "Add to PATH" 체크).
2. ZIP을 풀고 `app/run.bat` 더블클릭 → 없는 모듈만 자동 설치 → 브라우저에 화면이 열림. 종료는 터미널에서 Ctrl+C.
3. 처음 실행 때 `storage/history.db`(기록 DB)가 자동 생성됨. 이 파일이 이력 전부이므로 **주기적으로 복사해 백업**.

## 0. 화면 구성
- **홈**: 할 일 세 가지(새 요구서 처리 / 과거 답변 등록 / 기록에 묻기)와 현황 숫자. **새 요구서 처리**는 1 요구서 읽기 → 2 수치 맞춰 보기 → 3 회신 초안의 한 흐름이며 위쪽 단계 표시와 아래 '이전/다음 단계' 버튼으로 오간다. 각 단계의 파란 버튼이 다음 단계로 넘어가는 길.
- 샘플 파일 선택칸은 평소 실행에 없다. 심사·시연 때만 `run_demo.bat`(APP_DEMO=1)으로 띄우거나, 설정 → 백업·초기화 → '시연 데이터 넣기'로 가상 데이터를 넣는다.

## 1-0. 갱신 받는 방법
- 제출 ZIP은 심사용 고정본. 개발 중 갱신을 자주 받으려면 GitHub에서 한 번만 받아 두고(`git clone -b claude/demo-refinement-efn737 https://github.com/lts134/ebsjajucenter.git`, 또는 GitHub Desktop) 이후에는 `app/update.bat`만 실행하면 최신 코드를 받아 바로 띄운다.
- 기록 DB(`storage/history.db`)·출력물(`storage/out/`)은 git 관리 밖이라 갱신해도 지워지지 않는다. 이 폴더의 코드 파일을 직접 고치면 갱신 때 충돌하므로 고치지 않는다.
- 앱이 떠 있는 상태에서 받으면 반영되지 않는다. 터미널에서 Ctrl+C로 끄고 `update.bat`.

## 1-1. 여러 사람이 쓰는 서버 모드
1. 부서 공용 PC(또는 소형 서버)에서 `run_server.bat`(리눅스·맥은 `run_server.sh`) 실행 → 같은 망의 PC에서 `http://<공용PC 이름 또는 IP>:8501` 접속.
2. 접속자마다 **설정 → 공급자·키**에 자기 키를 넣고 **적용**. 키는 그 브라우저 세션에만 있고 서버 파일·다른 접속자에게 가지 않음. 탭을 닫으면 사라지므로 다음 접속 때 다시 입력.
3. 운영자가 공통 키를 쓰게 하려면 서버 환경변수에 키를 두면 됨 — Anthropic `ANTHROPIC_API_KEY`(필요 시 `ANTHROPIC_WORKSPACE_ID`), OpenAI 호환 `OPENAI_API_KEY`(게이트웨이면 `OPENAI_BASE_URL`), Gemini `GEMINI_API_KEY`. 기본 공급자는 `LLM_PROVIDER=anthropic|openai|gemini`, 기본 모델은 `LLM_MODEL`. 이때 접속자는 빈 칸으로 두어도 동작하며, 비용은 그 키로 합산됨.
4. 기록 DB(`storage/history.db`)는 모두가 공유(부서 공동 이력). 동시 쓰기를 위해 WAL 모드로 동작하며 `history.db-wal`·`-shm` 파일이 함께 생김(백업 시 셋 다 복사하거나 앱을 끈 뒤 복사).
5. 사이드바의 담당자·검토자 이름도 세션별. 접속자 인증(로그인)은 없으므로 **사내망 안에서만** 열고, 외부 인터넷에 노출하지 말 것 [확인 필요: 사내 보안 규정].
6. 공급자는 설정 → AI 연결에서 고름: **Anthropic Claude / OpenAI 호환(OpenAI·Azure·사내 게이트웨이) / Google Gemini / 사용 안 함**. 어느 것을 골라도 기능은 같다(요구서 추출·초안·대화 처리·이력 질의). 연결 테스트가 그 키로 쓸 수 있는 모델 목록을 가져오므로 거기서 고르면 된다. 공급자마다 안전 분류기가 응답을 거절하면 화면에 "응답을 거절했습니다"로 표시되고 규칙 경로가 있는 기능은 규칙으로 대체된다. 그 밖의 백엔드는 `docs/provider_template.py`를 복사해 `app/provider_<이름>.py`로 두고 재시작.

## 1-2. 클라우드에 올리기(권장 운영 방식)
Firebase Hosting(정적 파일 전용)에는 올릴 수 없다. 대신 같은 Google 프로젝트의 **Cloud Run**에 `deploy_cloudrun.sh`로 올린다: 요청 없으면 인스턴스 0으로 줄어 쓴 만큼만 내고, 기록 DB는 Litestream이 Cloud Storage에 실시간 복제해 컨테이너가 꺼져도 유지된다. 외부 URL이므로 `APP_PASSWORD`를 반드시 둔다. 비용·절차·보안·한계는 `docs/배포_클라우드.md`.

## 2. Claude API 연결
| 단계 | 내용 |
|---|---|
| 키 준비 | console.anthropic.com에서 API 키 발급. 워크스페이스 안에서 만든 키 권장(아니면 설정 화면에 워크스페이스 ID도 입력) |
| 입력 | 설정 화면 **공급자·키**에 붙여 넣고 **적용**(브라우저 세션에만 보관, 앱을 끄면 사라짐). 혼자 쓰는 PC에서 상시 사용은 `set_key.bat` 실행 → 키 입력(화면에 안 보임) → 사용자 환경변수에 저장 → 앱 재실행. 지우려면 `unset_key.bat`. 이 PC 계정으로 앱을 띄우는 사람은 모두 그 키를 쓰게 되므로 공용 PC·서버 모드에서는 쓰지 말 것 |
| 확인 | **연결 테스트** → 모델명·왕복시간·사용 가능 모델 목록(단가 포함). 목록이 '모델' 선택칸에 반영되므로 골라서 **적용** |
| 크레딧 | 잔액 0이면 "credit balance is too low" → 콘솔 Plans & Billing 충전 |
| 키가 없을 때 | 모든 화면이 규칙 기반으로 동작. 추출 정확도는 정형 서식에 한정 |

사내망에서 연결이 안 되면: 설정 화면 오류 문구를 기록(프록시·방화벽 여부) → 정보보안 담당에 api.anthropic.com 허용 요청 또는 규칙 경로로 운영.

## 3. 실데이터 전환
1. **값 입력은 한 칸**(과거 답변 등록·2단계 공통): 엑셀·CSV·회신 공문(hwp·hwpx·docx·pdf)을 종류 구분 없이 **여러 개 한 번에** 올리면 파일마다 아래에 읽은 결과가 쌓이고 전부 합쳐 저장된다. 파일을 빼려면 올린 목록의 ×. 파일이 없으면 아래 '파일 없이 직접 입력'.
   - 집계 엑셀/CSV: 긴 형식(`지표명, 센터명, 기준일, 값` + 선택 `지표 정의, 집계기간, 추출시점, 원자료 버전`)이면 그대로 읽음. 구형 `.xls`, 이름만 `.xls`인 사내 시스템 내려받기(XML 스프레드시트 2003·HTML 표·웹 보관 파일·탭 구분 텍스트)도 내용을 보고 판별해 읽음. 열 머리글에 월(`2025.12 진행`)이 있는 **월별 펼침 표**는 열마다 그 월의 말일이 기준일이 되고, 같은 이름의 열은 한 지표로 묶여 지표명을 한 번만 정하면 됨. 센터 이름이 빈 행(상위 구분 소계)은 넣지 않음. 한글 컬럼명·'67.8%'·'1,234'·'2026. 6. 30.' 표기, cp949 CSV 허용. 시트가 여러 개면 고름.
   - 실적표 서식 그대로(제목 행·병합 머리글·행=센터·열=지표·합계 행)를 올리면 "가로 펼침 표로 읽었습니다" 안내와 함께 **열 매핑** 칸이 뜸: 센터 열, 값 열, 기준일(제목의 '… 기준' 날짜가 자동), 값 열별 지표명(사전에 있으면 정규 지표명) 확인 → 아래 표로 변환됨. 합계·소계·평균 행은 기본 제외. 키가 있으면 **Claude로 열 매핑 제안** 버튼으로 초안을 받을 수 있으나 확정은 담당자가 함.
   - 회신 문서의 표(hwp·hwpx·docx·pdf): 그때 보낸 공문을 그대로 올리면 문서 안 표를 찾아 같은 열 매핑으로 읽음. 공문 틀 표도 목록에 나오며 숫자가 많은 표가 기본 선택. 기준일이 표가 아니라 본문에만 있으면 직접 입력. 출처는 "회신 문서(파일명) 표에서 추출"로 남음. HWP(5.0 구형식)는 PC 안에서 HWPX로 변환해 읽음(외부 전송 없음). 암호·배포용 문서는 한글에서 일반 HWPX로 다시 저장. 스캔 PDF는 글자가 없어 불가.
   - 직접 입력: 표 파일이 없을 때 화면에서 행을 추가해 입력.
   - **여러 파일·여러 표**: 문서 안에 표가 여러 개면 '문서 안의 표'에서 여러 개를 고를 수 있고, 고른 표마다 열 확인이 뜬다. 같은 지표·센터·기준일이 두 곳에 있으면 경고가 뜨고 나중에 올린 파일의 값만 남는다. 저장된 값마다 출처 파일·표가 따로 남는다.
2. **지표 사전**: `normalize.py`의 `CANON`에 부서 지표명과 동의어 추가. 추출·검색·제안·충족 검사·Claude 스키마가 모두 이 사전을 씀.
3. **데이터 카탈로그**: `suggest.py`의 `CATALOG`에 지표별 데이터 출처·담당 기입.
4. **회신 서식**: 부서 회신 HWPX를 한글에서 열어 `{{수신}} {{발신}} {{제목}} {{요구항목}} {{본문}} {{차이사유}} {{산출근거}} {{담당자}}`와 표 행에 `{{row.no}} {{row.indicator}} {{row.center}} {{row.base_date}} {{row.value}}`를 넣고 `templates/`에 저장. 자리표시자가 여러 run으로 쪼개져 저장돼도 인식됨(2026-10-04 보강). 출력물은 **반드시 한글에서 열어 모양 확인**(저장 성공이 표시 정상을 보장하지 않음).
5. **점검 사례**: 실제 요구서 몇 건을 `testcases.py`에 정답표와 함께 추가 → `python check_llm.py`로 재채점.

## 4. 일상 운영 절차
| 시점 | 할 일 |
|---|---|
| 월 집계 완료(요구서와 무관) | **지표 데이터**에 월별 집계(등원율·등록 학생 수 등)를 올려 둠. 같은 지표·센터·기준일은 새 값으로 바뀜. 이후 새 요구서의 같은 지표·기준일은 2단계에서 자동으로 채워짐 |
| 기초자료 한 번에 적재 | **지표 데이터 → 통합 대시보드에서 한 번에 가져오기**: 현황 대시보드를 브라우저에서 페이지 저장(.html)한 파일을 올리면 출결·진단검사·관리인원·상담·이용현황 값과 센터 명부가 들어감. 대시보드가 갱신되면 다시 저장해 올리면 됨(같은 지표·센터·기준일은 새 값으로, 명부는 통째로 교체). 계정·연락처 영역은 읽지 않음 |
| 사업 자체 문의 대비 | **참고 문서**에 관리·운영지침·운영 매뉴얼 PDF를 올려 둠. 이후 대화·기록에 묻기에서 "운영 시간은?", "이용 대상은?" 같은 질문에 문서 문구와 쪽을 근거로 답함. 개정판이 나오면 같은 제목으로 다시 올리면 교체됨 |
| 화면 구성(2026-10 재편) | 메뉴는 **업무**(홈·현황·검토·승인) / **자료**(지표 데이터·참고 문서·과거 답변 등록) / **기록**(찾기·고치기 + 물어보기 두 보기) / 설정. '새 요구서 처리' 3단계 화면은 메뉴에서 빠지고 홈 검수의 '단계 화면에서 자세히 고치기'로만 들어감 |
| 요구 건 상태 | 접수 → 처리 중 → 확정 → 발송 → 종결(+보류). 등록·확정·발송 때 자동으로 넘어가고, 종결·보류·담당자·메모는 **현황 → 건 관리** 또는 기록 → 요구서 수정에서 직접. 현황 표는 기본으로 종결을 숨김(상태 칩으로 선택) |
| 매일 아침 | **홈** 상단 '오늘 할 일' 띠: 기한 3일 이내 · 확정했지만 미발송 · 팀장 검토 대기 · 지난달 기준 지표 데이터 유무. 각 칸 아래 버튼으로 바로 이동. 답 아래 **다음 행동 칩**(요청 주체·기한 적기, 예상 질문 보기, 기록에 등록 등)을 누르면 말하지 않고도 다음 단계로 감 |
| 새 요구서 접수 | **홈(대화)** 에 요구서를 붙이고 "요구하는 것들 작성해 줘" → 읽기·등록·자료 계획·값·대조·사유·초안·HWPX까지 자동 → 검수 패널에서 확인 → **승인하고 확정**(확인 목록: [확인 필요] 수·빈 사유·미충족 항목·개인정보 패턴·미반영 수정 → **확정**). 세부 조정은 대화로("9월까지 전부로", "센터C 사유는 …") 또는 '단계 화면에서 자세히 고치기'. 사유·초안을 고치면 '반영 전' 표시가 뜨고 **HWPX 다시 만들기**(확정 때는 자동 반영) |
| 검수 화면 보는 법 | 위에서 아래로 ① 수치와 대조 한 표(이번·지난번·차이·판정·사유, 노랑 = 다름·사유 있음, 빨강 = 다른데 사유 비어 있음) → ② 차이 사유 입력 → ③ 회신 초안 → ④ 예상 질문 → 확정. 머리의 진행 칩(읽기·등록·값·대조·사유·초안·HWPX·확정)으로 어디까지 됐는지 봄 |
| 차이 사유 적기 | 검수 → 대조·차이 사유의 입력칸 옆 **문구** 버튼: 자주 쓰는 사유 문구(확정 때 쓴 사유가 자동으로 쌓임, 많이 쓴 순)에서 고르거나 지금 문구를 서랍에 저장. 설정 → 서식·사전에서 직접 추가·삭제 |
| 확정 뒤 보내기 | 검수 패널이 **보내기 카드**로 바뀜: 회신 HWPX 받기 → 메일 제목·본문(복사용, 앱은 메일을 보내지 않음) → 보낸 뒤 **발송 기록 저장**(보낸 곳·방법·날짜). 현황에서 '확정(미발송)'과 '발송 완료'가 구분됨. 다음 건은 **＋ 새 요구 시작**(대화 상단에도 있음) |
| 처리 중 다른 메뉴를 눌렀을 때 | 처리는 계속되고 결과는 보관됨. 홈으로 돌아오면 '이어서 기다리는 중'으로 붙어 결과를 보여 줌. 처리 중에는 입력칸이 잠김 |
| 요구서 파일 없이 접수(전화·구두) | 홈(대화)에 집계 파일을 붙이고 **말로** 요구를 적는다: "25년 12월부터 26년 8월까지 전체 센터의 센터별 등원율 요청이 들어왔어. 작성해 줘" → 문장을 요구 항목으로 적고(요청 주체·접수일·기한은 미기재로 두었다가 말하면 반영), 지표 데이터에서 그 기간의 기준일을 전부 가져와 초안·HWPX까지. "등록은 빼고 파일만 만들어 줘"라고 하면 기록 등록을 **승인 때까지 미룸**(검수 패널에 '요구서 미등록(승인하면 등록)' 표시) |
| 집계 완료 | 2단계(수치 맞춰 보기): 먼저 **자료 계획**을 본다 — 항목마다 지표 데이터(우선)·과거 제출값의 범위를 보고 낼 기준일을 제안함: 요구 기준일이 있으면 그 값, 없으면 '월별'이면 있는 달 전부·'연도별'이면 연도 말·그 외는 최신, 요구 기준일이 없으면 그 이전 가장 가까운 것(차이를 회신에 밝히라고 안내). 기준일을 고친 뒤 **계획대로 가져오기**(파일 불필요). 새로 산출할 항목은 **입력 서식(엑셀)** 을 내려받아 값만 채워 올리거나 실적표·회신 공문을 그대로 올림(겹치면 올린 값 우선) → '문구 후보 받기' → 후보 적용 또는 직접 입력 → 점검표 엑셀 저장 → 확정하고 3단계로 |
| 회신 작성 | 3단계(회신 초안) → 빠진 항목 검사·AI 추가 점검 → '예상 질문 보기'로 후속 질문·준비 자료 확인 → 개인정보 검사 → HWPX·제출 묶음 ZIP(예상 질문 포함) → 초안 저장하고 팀장 검토 요청 |
| 과거 확인 | 기록에 묻기에서 자연어로 질문("감사실에 등원율 언제 어떤 값으로 냈지?"). 답의 '근거 레코드'를 펼쳐 조회 내역 확인. 키 없으면 키워드 검색 |
| 팀장 | 검토·승인에서 승인/반려(의견 기록) |
| 제출 후 | 과거 답변 등록에서 최종 제출본을 넣음(다음 대조의 기준이 됨) |
| 잘못 넣었을 때 | 과거 답변 등록 직후라면 저장 메시지 옆 **되돌리기**. 그 뒤에는 **기록 조회**에서 요구서를 펼쳐 **수정**(요청 주체·접수일·기한·제목·항목) 또는 제출값 표를 고쳐 **값 저장**, **삭제**(확인 체크 → 삭제 버튼). 요구서 삭제는 항목·제출값·차이 사유·초안·검토 기록을 함께 지우며 되돌릴 수 없음. **지표 데이터** 묶음을 지우면 그 묶음이 덮어썼던 이전 값이 되살아남(재적재는 이전 값을 지우지 않고 '대체됨'으로 둠) |
| 월 1회 | 설정 → **백업·초기화 → 백업 파일 만들기 → 내려받기**(기록 DB 한 파일)를 사내 저장소에 보관. 30일이 지나면 설정 화면에 경고가 뜸. 되돌릴 때는 같은 화면 **복원**(덮어쓰기 전 현재 기록은 서버 안 backup/에 자동 보관). 현황의 관리대장 엑셀 보관, `python run_checks.py` |
| 요청 주체 표기 통일 | 설정 → 서식·사전 → **요청 주체 사전**에 표준 이름·별칭·유형을 넣으면 요구서를 읽을 때 같은 기관으로 통일되고 입력칸에서 자동완성됨. 현황 '요청 주체별'이 갈라져 보이면 별칭을 넣고 **기록에 표기 통일 적용** |
| 지표 추가·동의어 수정 | 설정 → 서식·사전 → **지표 사전·데이터 카탈로그** 표에서 지표·동의어·자료 출처·담당을 고쳐 **저장**하면 바로 적용(재배포 불필요). 잘못되면 **코드 기본값으로 되돌리기** |
| 지표 데이터 빠진 곳 확인 | 지표 데이터 → 들어 있는 것: 지표 × 월 히트맵(칸 숫자 = 센터 수, 빨강 = 없음)과 '명부 대비 빠진 센터'. 지난달 기준 자료가 없으면 경고 |
| 처음 설치·부서 정보 | 설정 → **서식·사전 → 조직 설정**: 부서장 이름·내선·부서명·기관명을 저장(기록 DB에 저장되어 접속자 모두에게 적용, 답변자료 【확인】 줄·메일 문안에 쓰임) |
| 배포 확인 | 사이드바 맨 아래 **빌드 날짜·커밋**이 방금 배포한 것과 같은지 본다(배포 스크립트가 빌드 때 기록) |

## 5. 장애·오류 대응
| 증상 | 조치 |
|---|---|
| "Claude 호출 오류로 규칙 기반 결과입니다" | 설정 화면 연결 테스트로 원인 확인(401 키, 403 워크스페이스, 404 모델명, 429 한도, 크레딧, 네트워크). 규칙 결과로 계속 진행 가능 |
| 파일을 읽지 못했습니다(필수 컬럼 없음 / 기준일 날짜 오류 / CSV 인코딩 / 같은 지표·센터·기준일 중복 행) | 오류 문구에 행 번호·허용 컬럼명이 표시됨. 엑셀에서 수정하거나 'CSV UTF-8'로 다시 저장. 중복 행은 한 기준일에 센터당 한 행만 남길 것 |

| 문서에서 표를 찾지 못했습니다 | hwpx·docx는 표 개체에서 직접 읽음(공문 틀 표 안의 중첩 표, 병합 머리글 포함). 오류 아래 '진단' 펼침에서 추출된 본문을 확인: 본문이 비어 있으면 배포용(암호화) 문서나 그림으로 된 문서. PDF는 글자 추출이 되는 파일만. 스캔본·그림 표는 '직접 입력' |

## 6. 점검·배포
- `python run_checks.py`(또는 `run_checks.bat`): ruff → pytest 38건 → 추출 품질 점검 → 6단계 화면 흐름. 모두 '통과'여야 배포.
- `python make_submission_zip.py`: 기록 DB·출력물·캐시를 뺀 제출용 ZIP을 `../dist/`에 생성.
- `python docs/capture_screens.py`: 8개 화면 캡처 재촬영(머리말 참조).

## 7. 보안 수칙
- API 키·워크스페이스 ID를 코드·문서·채팅에 남기지 않기. 노출된 키는 콘솔에서 즉시 폐기·재발급.
- `run.bat`은 localhost에만 열림(혼자 쓰기). 여러 사람은 `run_server.bat`로 열되 사내망 안에서만.
- 설정 화면에 넣은 키는 그 접속자의 브라우저 세션에만 보관됨(서버 파일·다른 접속자와 공유되지 않음). 호출 기록·비용도 세션별.
- 개인 단위 원자료(출결 명단 등)는 앱에 올리지 않기. 제출값은 센터 단위 집계값만.
- 2단계·3단계의 개인정보 검사 경고가 뜨면 제출 전 삭제·가명 처리. 홈 검수의 확정 전 확인 목록에서도 막힘(확인 체크 뒤에만 확정).
- 통합 대시보드 **저장 파일(.html)에는 '계정정보' 영역의 아이디·비밀번호가 평문으로** 들어 있을 수 있음. 앱은 그 영역을 읽지 않고 파일도 저장하지 않지만, 파일 자체를 메일·메신저로 보내지 말고 쓰고 난 사본은 지울 것. 이미 공유된 적이 있으면 해당 비밀번호 변경.
- 비용 확인: 사이드바 '이 세션 호출 N회 · 추정 $ · 캐시 읽기'와 설정 → 호출 기록(`cache_read_tokens`). 단가표는 공개 가격 캐시이므로 청구는 콘솔 기준 [확인 필요].
- 기록 DB는 부서 공용 PC 또는 암호화된 공유 폴더에 두고 접근 권한 관리 [확인 필요: 사내 규정].
