# 운영 매뉴얼 — EBS 대외 요구자료 대응 에이전트

## 1. 설치·실행 (Windows PC)
1. Python 3.11 이상 설치(설치 시 "Add to PATH" 체크).
2. ZIP을 풀고 `app/run.bat` 더블클릭 → 없는 모듈만 자동 설치 → 브라우저에 화면이 열림. 종료는 터미널에서 Ctrl+C.
3. 처음 실행 때 `storage/history.db`(이력 DB)가 자동 생성됨. 이 파일이 이력 전부이므로 **주기적으로 복사해 백업**.

## 2. Claude API 연결
| 단계 | 내용 |
|---|---|
| 키 준비 | console.anthropic.com에서 API 키 발급. 워크스페이스 안에서 만든 키 권장(아니면 설정 화면에 워크스페이스 ID도 입력) |
| 입력 | 설정 화면 'API 키(세션 한정)'에 붙여 넣기(파일에 저장되지 않음, 앱을 끄면 사라짐). 상시 사용은 `set ANTHROPIC_API_KEY=...` 환경변수 |
| 확인 | **연결 테스트** → 모델명·왕복시간·사용 가능 모델 목록(단가 포함). 성공한 모델 id를 '모델명' 칸에 넣어 고정 권장 |
| 크레딧 | 잔액 0이면 "credit balance is too low" → 콘솔 Plans & Billing 충전 |
| 키가 없을 때 | 모든 화면이 규칙 기반으로 동작. 추출 정확도는 정형 서식에 한정 |

사내망에서 연결이 안 되면: 설정 화면 오류 문구를 기록(프록시·방화벽 여부) → 정보보안 담당에 api.anthropic.com 허용 요청 또는 규칙 경로로 운영.

## 3. 실데이터 전환
1. **제출값 엑셀 컬럼**: `지표명, 센터명, 기준일, 값, 지표 정의, 집계기간, 추출시점, 원자료 버전`. 한글 컬럼명·'67.8%'·'1,234'·'2026. 6. 30.' 표기, cp949 CSV 모두 허용. 시트가 여러 개면 업로드 후 시트를 고름.
2. **지표 사전**: `normalize.py`의 `CANON`에 부서 지표명과 동의어 추가. 추출·검색·제안·충족 검사·Claude 스키마가 모두 이 사전을 씀.
3. **데이터 카탈로그**: `suggest.py`의 `CATALOG`에 지표별 데이터 출처·담당 기입.
4. **회신 서식**: 부서 회신 HWPX를 한글에서 열어 `{{수신}} {{발신}} {{제목}} {{요구항목}} {{본문}} {{차이사유}} {{산출근거}} {{담당자}}`와 표 행에 `{{row.no}} {{row.indicator}} {{row.center}} {{row.base_date}} {{row.value}}`를 넣고 `templates/`에 저장. 자리표시자가 여러 run으로 쪼개져 저장돼도 인식됨(2026-10-04 보강). 출력물은 **반드시 한글에서 열어 모양 확인**(저장 성공이 표시 정상을 보장하지 않음).
5. **점검 사례**: 실제 요구서 몇 건을 `testcases.py`에 정답표와 함께 추가 → `python check_llm.py`로 재채점.

## 4. 일상 운영 절차
| 시점 | 할 일 |
|---|---|
| 새 요구서 접수 | ② 분석 → 이력 등록 → ⑦에서 D-day 확인 |
| 집계 완료 | ③ 대조 → '사유 문구 후보 제안' → 후보 적용 또는 직접 입력 → 점검표 엑셀 저장 → 확정 |
| 회신 작성 | ④ 초안 → 충족 검사·Claude 추가 점검 → '어떤 질문이 올까?'로 후속 질문·준비 자료 확인 → 개인정보 검사 → HWPX·제출 묶음 ZIP(예상 질문 포함) → 검토 요청 |
| 과거 확인 | ⑧ 이력에 묻기에서 자연어로 질문("감사실에 등원율 언제 어떤 값으로 냈지?"). 답의 '근거 레코드'를 펼쳐 조회 내역 확인. 키 없으면 키워드 검색 |
| 팀장 | ⑤ 승인/반려(의견 기록) |
| 제출 후 | ①에서 최종 제출본을 '과거 자료'로 등록(다음 대조의 기준이 됨) |
| 월 1회 | `storage/history.db` 백업, ⑦ 관리대장 엑셀 보관, `python run_checks.py` |

## 5. 장애·오류 대응
| 증상 | 조치 |
|---|---|
| "Claude 호출 오류로 규칙 기반 결과입니다" | 설정 화면 연결 테스트로 원인 확인(401 키, 403 워크스페이스, 404 모델명, 429 한도, 크레딧, 네트워크). 규칙 결과로 계속 진행 가능 |
| 파일을 읽지 못했습니다(필수 컬럼 없음 / 기준일 날짜 오류 / CSV 인코딩 / 같은 지표·센터·기준일 중복 행) | 오류 문구에 행 번호·허용 컬럼명이 표시됨. 엑셀에서 수정하거나 'CSV UTF-8'로 다시 저장. 중복 행은 한 기준일에 센터당 한 행만 남길 것 |
| HWP(구형식) 업로드 | 한글에서 HWPX로 저장 후 업로드 |
| ⑧에서 "도구 호출 횟수 한도" 메시지 | 질문을 좁혀 다시(지표·기간·기관 중 하나 명시). 한도는 8회 |
| 이력 DB 손상("file is not a database" 등) | 앱이 자동으로 `.broken`으로 이름을 바꾸고 새 DB 생성. 백업본으로 교체 |
| "database is locked" 오류 | 다른 창·탭이 같은 DB에 쓰는 중. 15초 대기 후에도 나면 다른 창을 닫고 다시 시도(이력 파일은 건드리지 않음) |
| 요구서에 전화·이메일이 있는데 Claude로 보내도 되나 | 전송 전에 자동 마스킹됨(②·① 추출 결과 아래 '마스킹 후 전송' 표시). 담당자 이름 등 자유 문구는 마스킹 대상이 아니므로 원문에서 지울 것 |
| 화면이 멈춤 | 터미널 Ctrl+C 후 `run.bat` 재실행. 세션 입력값(키 등)은 다시 입력 |

## 6. 점검·배포
- `python run_checks.py`(또는 `run_checks.bat`): ruff → pytest 38건 → 추출 품질 점검 → 6단계 화면 흐름. 모두 '통과'여야 배포.
- `python make_submission_zip.py`: 이력 DB·출력물·캐시를 뺀 제출용 ZIP을 `../dist/`에 생성.
- `python docs/capture_screens.py`: 8개 화면 캡처 재촬영(머리말 참조).

## 7. 보안 수칙
- API 키·워크스페이스 ID를 코드·문서·채팅에 남기지 않기. 노출된 키는 콘솔에서 즉시 폐기·재발급.
- 설정 화면에 넣은 키는 앱 실행(프로세스) 동안 메모리에만 있음. 한 PC에서 한 사람이 쓰는 전제. 여러 사람이 같은 실행을 공유하는 운영(서버 배포)이면 세션별 키 보관으로 바꿔야 함.
- 개인 단위 원자료(출결 명단 등)는 앱에 올리지 않기. 제출값은 센터 단위 집계값만.
- ③·④의 개인정보 검사 경고가 뜨면 제출 전 삭제·가명 처리.
- 이력 DB는 부서 공용 PC 또는 암호화된 공유 폴더에 두고 접근 권한 관리 [확인 필요: 사내 규정].
