# 개선 검토서 — 전체 최적화(토큰·결과 품질·사용성·견고성)

작성일 2026-10-08 · 대상 `app/` 전체(배포본 Cloud Run 포함) · 근거: 코드 정독 3회(토큰·프롬프트 / 사용성 / 정확성·견고성 감사), pytest 145건, 화면 흐름 검사(AppTest) 통과

## 요약
- 모델 호출 비용의 큰 몫이던 **반복 전송(시스템 프롬프트·도구 정의·값 행 통째 전송)** 을 캐싱과 요약 payload로 줄였고, 추출·분류처럼 판단이 단순한 호출은 추론 강도를 낮췄다.
- 결과물 품질에서 **값이 바뀌어 보이던 두 곳**(소수 반올림 표기, 센터 표기가 달라 두 행으로 갈라지던 것)과 **번호가 어긋나던 답변자료**(지표 둘로 나뉜 항목)를 고쳤다.
- 사용성은 **확정 전 확인 목록 → 확정 → 보내기(메일 문안·발송 기록) → 새 요구 시작** 흐름을 만들고, 처리 중 다른 메뉴를 눌러도 결과를 잃지 않게 했다.
- 실측(정확도·비용·지연)은 사용자 키로 돌려야 하므로 [확인 필요]로 남기고 측정 방법을 아래에 적었다.

## 검토 기준
1. 토큰: 같은 결과를 더 적은 입력·출력 토큰으로 내는가(캐시 적중, payload 크기, 중복 호출, 출력 상한).
2. 결과 품질: 값·날짜·센터명을 **바꾸지 않고** 옮기는가, 번호·표·근거가 요구 항목과 일치하는가, 지어낸 내용이 없는가.
3. 사용성: 담당자가 확정·발송까지 멈추지 않고 가는가, 고친 내용이 반영됐는지 보이는가, 되돌릴 수 있는가.
4. 견고성·보안: 중단·재실행·잘못된 입력에 데이터가 깨지지 않는가, 외부 문자열이 화면·모델로 안전하게 가는가.

## 판단 근거와 조치 (적용)

### 1. 토큰
| 항목 | 전 | 후 | 근거 |
|---|---|---|---|
| 시스템 프롬프트·도구 정의 | 매 호출 전송 | `cache_control`(1시간) 접두사 캐싱, 캐시 읽기·쓰기 토큰을 호출 기록·비용에 반영 | 대화 처리는 도구 턴마다 같은 접두사를 다시 보냄 |
| 초안 payload | 값 행 전부 + 사유 + 근거 | 항목 요약(지표별 건수·센터 수·기준일 범위)·대조 건수·지표별 근거만. 차이사유·산출근거 칸은 코드 생성 | 모델은 문안만 쓰고 수치는 표가 담당 |
| 사유 후보 | 차이 행마다 호출 | (지표, 단서)로 묶어 한 번, 이미 기록된 사유가 있는 키는 제외 | 같은 단서면 같은 후보 |
| 지표 분류 | 모델 추출 뒤 다시 분류 호출 | 모델 추출이면 분류 생략(규칙 경로만 보조 분류) | 추출 스키마가 이미 지표 enum |
| 도구 결과 | 전체 행 전송 | 그룹·상한(센터 60·이력 40·개요 30), 7,600자 잘림 안내("전체가 아니므로 범위를 좁혀 다시") | 잘린 결과를 '없음'으로 단정하던 것 방지 |
| 상태줄 | 지표 31개 나열 | 같은 범위끼리 묶어 한 줄 | 대시보드 적재 뒤 매 턴 수백 토큰 |
| 추론 강도 | 전 호출 모델 기본 | 지표 분류·표 열 매핑·연결 테스트 low, 나머지는 설정값(기본/빠르게/보통/꼼꼼하게) | 판단이 단순한 호출 |
| 대화 기록 | 무한 누적 | 30블록 넘으면 요약 한 줄로 새로 시작, 확정·새 요구 시작 때 비움(중간을 자르지 않음) | 보존된 사고 블록을 자르면 400 오류·품질 저하 |
| 잘린 도구 호출 | 결과 없는 tool_use가 남아 다음 턴 400 | 오류 결과를 붙이고 "요청을 나눠서" 안내 | API 제약 |

### 2. 결과 품질
- **소수 표기**: 한 표 안에서 받은 값의 가장 긴 소수 자릿수(최대 3)로 통일. 61.25를 61.2로 보이던 반올림 제거.
- **센터 표기 통일**: 저장 시 명부 → 이미 저장된 표기 → 묶음 안 첫 표기 순으로 맞춰 'EBS 계룡 센터'/'EBS계룡센터'가 한 행으로. 대조도 같은 키로 짝을 맞춤.
- **답변자료 번호**: 같은 원문이 지표 둘로 나뉜 항목은 초안과 같이 한 번호, 표는 지표마다. 날짜로 시작하는 줄('2025. 12. 31. 기준…')을 번호로 오인해 글자를 떼던 것 수정. '각 월 말일'은 실제로 모두 월말일 때만.
- **기간 표현**: '2025. 12. ~ 2026. 8.'(점 표기), '2026년 상반기', '2026년 2분기'를 기간으로 읽음. '분기별'만 분기 말 선택.
- **산출 근거**: 'nan'·'None' 문자열이 근거로 들어가던 것 제외.
- **대시보드 가져오기**: '-'·빈칸·'1,234'·'61.3%' 값 처리, 기준일이 하나도 없을 때 오류 대신 안내.
- **프롬프트**: 추출 규칙의 모순(연도 보충 vs 추정 금지) 명시, 분류 프롬프트 중복 규칙 정리, 표 열 매핑에 월별 열·다중 센터 열·소계 행 지침.

### 3. 사용성
- 검수 패널 입력칸 키에 판 번호(rev)를 넣어 모델·코드가 초안을 새로 쓰면 칸도 새 내용으로 바뀜(이전 입력이 덮어쓰던 문제).
- 사유·초안을 고치면 '반영 전' 표시와 다시 만들기 버튼이 항상 보임. 확정 때는 사유 칸·한글 파일을 자동 반영.
- **승인하고 확정** 누르면 확인 목록([확인 필요] 수, 빈 사유, 미충족 항목, 개인정보 패턴, 미반영 수정, 요청 주체 미기재, 미등록) → **확정**. 개인정보 패턴만 확인 체크를 요구.
- 확정 뒤 **보내기 카드**: HWPX 받기, 메일 제목·본문(코드 생성, 복사용), 발송 기록(보낸 곳·방법·날짜) → 현황에 '확정(미발송)'/'발송 완료' 구분.
- **＋ 새 요구 시작**(대화 상단·보내기 카드). 확정이 끝난 작업에 새 요구가 오면 앞 건 기록을 고치지 않고 새 작업으로.
- 처리 중 다른 메뉴를 눌러도 결과를 잃지 않음(작업 자리에 스레드·큐 보관, 돌아오면 이어서 표시). 처리 중에는 입력칸 잠금.
- 말 없이 집계 파일만 붙이면 '확인'만 하고, 의뢰서가 붙었을 때만 자동으로 '작성'.
- 묶음·참고 문서 삭제는 확인 단계를 거침. 'None' 대신 '미기재'. 설정의 추론 강도는 선택칸, 키 지우기는 입력칸까지 비움.

### 4. 견고성·보안
- 지표 데이터 재적재는 삭제 대신 '대체됨' 표시(묶음을 지우면 이전 값이 되살아남, 사슬 복원). 기준일·값 정규화, 묶음 안 중복 정리.
- 비밀번호 비교의 인코딩 처리·실패 지연, HTML로 그리는 외부 문자열 이스케이프, 모델 출력의 이미지·태그 무해화.
- 배포: APP_PASSWORD 없이 외부 URL 배포 차단, 복제 저장소 복원 실패 시 기동 중단(빈 DB로 덮어쓰기 방지), 복제 보존 30일, 시간대 Asia/Seoul, 의존성 상한.
- 전화·주민번호 패턴에 한국어 조사 경계, 텍스트 파일 인코딩 판별(UTF-16·cp949).

## 측정 방법(사용자 키 필요) [확인 필요]
1. 추출 정확도·비용: 앱 폴더에서 `python check_llm.py` → `storage/llm_check_<날짜>.md`. 기본값으로 한 번, `set LLM_EFFORT=low` 뒤 한 번 더 돌려 '필수 재현'·비용·지연을 비교. 25/25가 유지되면 설정의 추론 강도 기본을 '빠르게'로 바꿔도 된다.
2. 캐시 적중: 설정 → '이 세션 호출 기록'에서 두 번째 대화 턴부터 `cache_read_tokens`가 0보다 크면 캐싱이 동작하는 것(첫 호출은 `cache_write_tokens`). 사이드바의 '캐시 읽기 Nk토큰'으로도 확인.
3. 대화 한 건 비용: 같은 의뢰서로 확정까지 간 뒤 사이드바 '추정 $'를 이전 배포와 비교.
