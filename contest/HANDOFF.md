# 활용수기 공모 온라인 접수 — 인수인계 문서

새 대화(또는 새 담당자)가 이 작업을 이어받을 때 가장 먼저 읽는 문서입니다. 설정 절차는 `README.md`, 이 문서는 **배경·결정 사항·현재 상태·남은 일**을 정리합니다.

마지막 갱신: 2026. 10. 7.

---

## 1. 사업 배경

- 2026년 **전국 대상** 자기주도학습센터 활용수기 공모를 온라인으로 접수·심사한다.
- 홍보와 사이트 팝업은 **위탁사 소관**이다. 이 작업의 범위는 **양식에 맞춘 접수**와 **심사 지원**이다.
- 이전 사례: 2026 포천형 공모는 자필 원고를 센터 코디네이터에게 직접 제출받았다(중1~3, 3명 선정). 제출 양식에는 인적사항, 센터 정보, 본문이 있고, 붙임으로 보호자 동의서, 개인정보 동의서, 재학증명서를 받았다.
- 대상 학생은 약 2,000명이지만, 실제 접수는 많지 않을 것으로 예상한다.

## 2. 결정 사항 (변경 시 이 표를 갱신)

| 항목 | 결정 | 이유 |
|---|---|---|
| 접수 방식 | 홈페이지 내 접수 페이지 (이메일·구글 폼 대신) | 양식 누락 방지, 접수대장 자동화, 블라인드 심사 연계. 구글 폼은 파일 업로드 시 구글 로그인이 필요해 제외 |
| 저장소 | Firebase (Firestore + Storage), **서울 리전 asia-northeast3** | 국내 저장, 보안 규칙으로 접근 통제. 구글 드라이브는 저장 위치를 지정할 수 없어 제외 |
| 화면 위치 | 접수 화면은 Firebase Hosting에 두고, 아임웹 `/event` 페이지에 iframe으로 삽입 | 아임웹 스타일 충돌 방지, 수정 시 아임웹 손대지 않음 |
| 학생 로그인 | 없음 | 참여 장벽 최소화. 대신 보안 규칙으로 "새 제출만" 허용 |
| 파일 | **타이핑 원고**, PDF 1개로 통합(원고 → 보호자 동의서 → 개인정보 동의서), 10MB 이하 | 심사·활용 편의 |
| 블라인드 | 원고에 이름·학교·센터명 기재 금지. 관리자 화면에서 심사번호 부여 후 심사용 ZIP(뒤쪽 동의서 쪽 제거 가능) | 공정성 |
| 중복 제출 | 마지막 제출본으로 심사. 관리자 화면에 최종본/이전본 표시 | |
| 재학증명서 | 접수 단계에서 받지 않음. 수상 후보자만 별도 확인 | 개인정보 최소 수집 |
| 접수번호 | **사용 안 함.** 완료 화면에 성명·학교·파일명·접수 일시 요약 표시 | 로그인이 없어 학생이 쓸 곳이 없음. 관리자는 성명·학교·일시로 검색 |
| 응모 기간 | 관리자 화면에서 설정·변경 (서버 시각 기준 차단) | 언제든 연장·변경 가능 |
| 개인정보 | 구글은 **처리위탁**(제3자 제공 아님). 처리방침에 수탁자 공개 필요 | |
| 결제 | Blaze 요금제. **결제 계정은 별도 개인 Google 계정**의 개인 유형으로 만들어 프로젝트에 연결 (공식 계정은 비즈니스 유형 프로필만 있어 개인 유형 생성 불가) | 예상 비용 월 1,000원 미만 |
| 디자인 | Pretendard 글꼴, 장식 최소화, 흰 바탕·얇은 선 | "AI가 만든 티" 제거 요청 반영 |
| 학년 | 중1~3, 고1~3 | 고등학생도 대상 |

## 5. 파일 구성

```
contest/
├─ HANDOFF.md          ← 이 문서
├─ README.md           ← 처음 설정 절차, 운영 유의사항
├─ firebase.json       ← Hosting(주소·보안 헤더) + 규칙 파일 위치
├─ .firebaserc         ← 기본 프로젝트 jajucenter-4ce99
├─ firestore.rules     ← 학생은 기간 내 새 제출만, 관리자만 조회·수정·삭제
├─ storage.rules       ← PDF·10MB·무작위 파일명, 덮어쓰기 금지, 관리자만 다운로드
├─ cors.json           ← 관리자 화면 PDF 다운로드 허용 주소
├─ imweb-embed.html    ← 아임웹 /event 코드 요소에 붙여넣는 코드
└─ public/
   ├─ apply.html       ← 학생 접수 화면
   └─ admin.html       ← 관리자 화면
```

Firestore 문서 구조: `config/contest`(openAt, closeAt), `config/admins`(uids 배열), `submissions/{무작위ID}`(신청 정보, filePath=`submissions/{ID}.pdf`)

## 6. 작업 시 유의사항 (다음 작업자에게)

- **보안 규칙을 바꾸면 에뮬레이터로 시험한 뒤 배포한다.** 이전 작업에서 규칙 41개 항목을 시험했고, Storage 덮어쓰기 허용 문제를 시험으로 발견해 `resource == null` 조건을 추가했다.
- 화면 수정 시 요소 ID(`statusBox`, `periodText`, `submitBtn`, `doneView` 등)를 바꾸면 동작이 깨진다.
- 아임웹 iframe 높이 조절은 `apply.html`의 높이 신호(`jc-contest-height`)와 `imweb-embed.html`의 수신 코드가 짝이다. 한쪽만 바꾸지 않는다.
- Firebase 설정값(`FIREBASE_CONFIG`)은 공개되어도 되는 값이다. 접근 통제는 보안 규칙이 한다.
- 사용자 선호: 공공기관 실무 문체, 과장 금지, 확인되지 않은 내용은 [확인 필요]로 표시, 근거·추론 구분.
